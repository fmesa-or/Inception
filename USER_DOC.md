# USER_DOC — User documentation

This document explains, for any end user or administrator, how to understand, start, stop and
check the status of the WordPress site deployed by this project.

---

## 1. What services does the stack provide?

The project runs three Docker containers, each with a single responsibility, connected to each
other through an internal network (`inception`):

| Service     | Function                                                                 |
|-------------|----------------------------------------------------------------------------|
| **nginx**   | Single public entry point. Serves the site over HTTPS (port 443) using TLSv1.3, and forwards PHP requests to the WordPress container. |
| **wordpress** | Runs WordPress together with PHP-FPM. This is what actually processes the site's logic (pages, posts, admin panel). |
| **mariadb** | Database where all the site's content is stored (users, posts, WordPress configuration). |

No service is reachable directly from outside except **nginx**, which is the only entry point
into the whole infrastructure.

## 2. Starting and stopping the project

All commands are run from the **root of the repository**, where the `Makefile` is.

### Start the project (rebuilding images)

```bash
make build
```

This creates the persistent data folders on the host, builds all three Docker images from
scratch, and starts the containers.

### Start without rebuilding (if already built before)

```bash
make up
```

### Stop the project

```bash
make down
```

Stops and removes the containers, but keeps the data (database and WordPress files).

### Stop and also delete the data

```bash
make downv
```

⚠️ This deletes the database and the site files. Use it only if you want to start fresh.

### Stop/start already existing containers without recreating them

```bash
make stop     # pauses the containers
make start    # starts them again
```

## 3. Accessing the website and the admin panel

First, make sure your machine resolves the project's domain to your local IP. This is configured
in the host's `/etc/hosts` file (outside this repository): 127.0.0.1 fmesa-or.42.fr

- **Website (front-end):** [https://fmesa-or.42.fr](https://fmesa-or.42.fr)
- **WordPress admin panel:** [https://fmesa-or.42.fr/wp-admin](https://fmesa-or.42.fr/wp-admin)

Any request over HTTP (port 80) is automatically redirected to HTTPS. Only port 443 is exposed
to the outside.

The browser will show an "untrusted certificate" warning the first time: this is expected, since
the TLS certificate is self-signed (generated by the nginx container itself, not by a public
certificate authority). You can accept the exception to continue.

## 4. Locating and managing credentials

Credentials (WordPress users, database passwords, admin credentials) are **not written in the
code** nor in any file tracked by git. They are defined in the `.env` file, located at
`srcs/.env`, which:

- Is not pushed to the repository (it is listed in `.gitignore`).
- Is automatically read by all three services through `env_file` in `docker-compose.yml`.

In that `.env` file you will find, among others:

- `WP_ADMIN_USER` / `WP_ADMIN_PASS` — credentials of the WordPress administrator user.
- `WP_SECOND_USER` / `WP_SECOND_PASS` — credentials of the second user (author role).
- `MYSQL_ROOT_PASSWORD`, `SQL_USER`, `SQL_PASS`, `MYSQL_DATABASE` — database credentials.

If you need to check or change them, edit that file and relaunch `make build` or
`make down && make up` so the containers pick up the new values (note: if a WordPress user
already exists, changing the password in `.env` does not retroactively update it in the already
created database; you would need to change it from the WordPress panel itself, or restart from
scratch with `make downv`).

## 5. Checking that the services are running correctly

### View container status

```bash
docker compose -f srcs/docker-compose.yml ps
```

All three services (`nginx`, `wordpress`, `mariadb`) should show `Up`. If any of them shows
`Restarting` persistently (more than 30-60 seconds), there is a problem.

You can also use the Makefile shortcut:

```bash
make show
```

which shows containers, images and volumes at a glance.

### View live logs

```bash
docker compose -f srcs/docker-compose.yml logs -f
```

Or the logs of a single service:

```bash
docker logs -f nginx_container
docker logs -f wordpress_container
docker logs -f mariadb_container
```

### Quick check from the browser

If `https://fmesa-or.42.fr` loads the WordPress site without connection errors, all three
services are running and communicating with each other correctly.

### Common issues

| Symptom | Likely cause |
|---|---|
| "Error establishing a database connection" | mariadb is still starting up; wait a few seconds — containers have `restart: always` and retry on their own. |
| Browser can't find the domain | Missing entry in `/etc/hosts`, or the nginx container is not `Up`. |
| Untrusted certificate | Expected, it's a self-signed certificate — accept the browser exception. |
